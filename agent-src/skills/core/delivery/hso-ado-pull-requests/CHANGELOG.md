# Changelog — hso-ado-pull-requests

All notable changes to this skill are documented in this file. Migrated from the inline `## Changelog` in `SKILL.md` per [ADR 0021](../../../agent/wiki/decisions/0021-skill-changelogs-in-sibling-file.md).

| Date | Author | Description |
|------|--------|-------------|
| 2026-08-17 | Meghan Reed | **Adopted the shared `Invoke-AdoRestMethod`** (`hso-shared-scripts/scripts/ADO-WebApi.ps1`). This skill was the one genuinely exposed ADO caller: its `Invoke-AdoPrRest` funnel ended in a bare `Invoke-RestMethod`, and one call — the work-item `ArtifactLink` PATCH in `LinkWorkItems` — bypassed the funnel entirely. **An unauthenticated ADO request does not return 401; it returns 302 to a sign-in page**, which `Invoke-RestMethod` follows, parses as HTML, and hands back as an object whose `.value` is empty — so a failed call reads as an empty result rather than an auth failure. Both sites now route through the shared invoker, which refuses the redirect, validates the body is JSON before parsing, and surfaces any non-2xx with its status code. Sibling skill `hso-ado-work-items` was never exposed — it wrote this guard, and the function was promoted out of it. No behaviour change on success: the funnel still builds UTF-8 request bytes itself (sidestepping 5.1's Latin1 default) and still overrides `Content-Type` per call, which the invoker maps onto `HttpWebRequest`'s restricted-header property — including the `application/json-patch+json` that `LinkWorkItems` requires. Verified live through the new path: `Get`, `List`, and a `Update` PATCH. |
| 2026-07-10 | Ivan Kurtev | **Fixed `LinkWorkItems` failing on a single work item.** The one-element patch array was piped to `ConvertTo-Json`, which unwraps it to a bare object, and the work-item PATCH endpoint rejects a non-array body with `VssPropertyValidationException: "You must pass a valid patch document"`. Now serialized via `ConvertTo-Json -InputObject @($patch)`, which preserves the array. Multi-ID calls were unaffected (arrays of 2+ survive the pipe); every single-ID link — the common case — failed. Surfaced linking Story #543 to PR #231. |
| 2026-06-13 | Ivan Kurtev | **Doc-only: explicit invocation contract.** Added a prominent "How to invoke the script (CRITICAL)" section with the proven copy-paste command — call the `.ps1` directly with `& "<path>" … *>&1 | Out-String` in the **current** session, foreground, and let it finish. Documented the anti-pattern (`powershell -File` / `pwsh -File` wrapper) that spawns a child runtime, re-imports MSAL.PS, can't see the warm in-session token, and produces 10–15 s of silence that gets misread as a hang and killed — the root cause of repeated "calls never reach ADO" failures. Rewrote all Operations Reference examples from the `powershell -File` form to the `& "<path>"` call-operator form. |
| 2026-06-13 | Ivan Kurtev | **Doc-only: headless-session sign-in hang gotcha (skill-gap #7).** Complements the 2026-06-10 system-browser fix: in a session with **no TTY/browser at all** (autonomous lane, CI/cron, background agent), an **expired** token cache leaves the sign-in flow blocking forever with no output. Documented the mitigation in the Authentication section — pass `-Pat <token>` (non-interactive) or pre-warm the cache in an attended session within the ~1h window; explicitly do **not** revert to `az repos pr create` (the non-ASCII mangling this skill exists to avoid). |
| 2026-05-12 | Meghan Reed | Initial skill — wraps ADO PR CRUD via REST API to sidestep the `az` CLI's Windows ANSI-codepage corruption of non-ASCII characters in PR bodies. Operations: Create, Update, Get, List, AddComment, LinkWorkItems. Auto-detects org/project/repo from `git remote` and source/target branches from local git state. Standard HSO PR body template (Summary / Why this matters / Test plan) documented for consultants. |
| 2026-06-10 | Ivan Kurtev | Fix the interactive sign-in hang under PowerShell 7. `ADO-Auth.ps1` now passes `-UseEmbeddedWebView:$false` to `Get-MsalToken`, forcing MSAL to use the system browser (localhost loopback) instead of its .NET-Framework-only embedded WebView. The embedded WebView never renders under PowerShell 7 (`pwsh`), so the call hung with no dialog — the reason agents fell back to `create-pr.sh`. The system browser works on both Windows PowerShell 5.1 and PowerShell 7, so the sign-in dialog now appears regardless of host, with no Azure CLI dependency. Also fixes `hso-ado-work-items` (shares the module). |
| 2026-06-10 | Ivan Kurtev | Fix `Update` (and `LinkWorkItems` / auto-complete) failing with "No api-version was supplied". Root cause was a PowerShell string-parsing bug: in URLs like `".../$PullRequestId?api-version=$ApiVersion"`, PowerShell treats `?` as part of the variable name and parses `$PullRequestId?api` as a single (undefined) variable — so both the id and the `?api` vanished, yielding `.../pullrequests/-version=7.1`. Braced the affected variables (`${PullRequestId}`, `${PrId}`, `${Repository}`) so the `?` ends the variable. `Get`/`Create`/`List`/`AddComment` were unaffected (they don't place a bare `$var` immediately before `?api-version`). |
| 2026-06-10 | Meghan Reed | **Bug fix:** PR operations failed for repos whose ADO **project or repository name contains a space** (e.g. `HSO-Forge / "Forge USA"`). `Resolve-GitRemoteContext` URL-*decodes* the remote to recover clean names, but the REST URL builders (`Get-PrBaseUrl`, `Format-PrUrl`, `LinkWorkItems`) then interpolated those decoded names directly, producing a URL with a **raw space** → malformed URI / 404. Now the project and repository segments are URL-encoded once (`[Uri]::EscapeDataString`) in `Confirm-Context` (`$ProjectEnc` / `$RepositoryEnc`) and used in every REST path. Fixes Create/Update/Get/List/AddComment/LinkWorkItems against space-named projects. |
