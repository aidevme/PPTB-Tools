# `agent/` — Project Wiki (hybrid)

AI-augmented project knowledge for this repo. A four-layer hybrid wiki: `raw` / `_inbox` / `wiki` /
`work`, no lifecycle numbering, anchor-page topics, external-source captures, strict frontmatter, and
an aggressive self-committing linter.

This is the **project tier** — one client, one engagement. It inherits the **product tier** live via
`shared/dv/agent/wiki/` (a gitignored junction; run `agent-src/sync/check-shared.ps1 -Strict` if a
`shared/dv/...` read comes back empty).

See [schema.md](schema.md) for the full conventions and the linter-enforced invariants.

## Four layers

| Layer | Purpose | Mutability |
|---|---|---|
| `raw/` | Sources of truth (files + external-source captures) | **Immutable** — read, never write |
| `_inbox/` | Not yet triaged | Transient — emptied by `aidevme-wiki-process-inbox` |
| `wiki/` | What we *know* — compiled, durable, cross-cutting | Agent-maintained |
| `work/` | What we *produce* — phase-oriented deliverables | Human + agent co-authored |

The test for *wiki vs work*: is this knowledge that outlives the project, or an artifact we're
delivering? Topics, ADRs, digests → `wiki/`. Specs, TDDs, test plans, deliverables → `work/`.

## Layout

```
agent/
├── index.md    catalog (categorised entry point) — regenerated by aidevme-wiki-lint
├── log.md      append-only chronological event stream (newest on top)
├── schema.md   folder + frontmatter + linter-invariant rules
├── raw/        IMMUTABLE sources (transcripts discovery screenshots exports) + captures
├── _inbox/     transient drop zone
├── wiki/       compiled knowledge (system digests topics sop reference people decisions)
└── work/       deliverables by phase (analysis specs design build testing deliverables)
```

## Core rules

1. **`raw/` is read-only.** Ingest skills write once; never edit afterwards.
2. **`_inbox/` is transient.** Drop anything; `aidevme-wiki-process-inbox` routes it.
3. **Every `wiki/`/`work/` page needs frontmatter** (see [schema.md](schema.md)).
4. **Markdown links only** — `[text](relative/path.md)` (Obsidian / VS Code / ADO compatible).
5. **Append to [log.md](log.md) on every significant write.**
6. **Durable knowledge extracted from work products belongs in `wiki/`.**
