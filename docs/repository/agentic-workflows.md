# GitHub Agentic Workflows

<!-- cspell:ignore agentics awf gitattributes noop powerplatformtoolbox recompiles safeoutputs -->

This guide explains how this repository uses [GitHub Agentic Workflows](https://github.github.com/gh-aw/) (gh-aw)
to run AI agents in GitHub Actions. It covers the one workflow we have so far, the **PPTB marketplace intake
review**, and what you need to add or change one.

It's for maintainers who know GitHub Actions but haven't used gh-aw yet. For the background and more
examples aimed at Power Platform repositories, see
[GitHub Agentic Workflows: the next evolution of repository automation](https://aidevme.com/github-agentic-workflows-the-next-evolution-of-repository-automation-for-power-platform-and-enterprise-developers/).

::: warning Technical preview
GitHub Agentic Workflows is in technical preview, and its syntax still changes between releases. This guide was
written against `gh aw` **v0.89.21**. If a command or field behaves differently, check the
[gh-aw documentation](https://github.github.com/gh-aw/) and run `gh aw upgrade`.
:::

## What an agentic workflow is

An agentic workflow is a Markdown file in `.github/workflows/`. It has two parts:

- **YAML frontmatter** says when the workflow runs, what the agent may read, which tools and network
  destinations it may use, and which writes it may ask for.
- **A Markdown body** says, in plain language, what the agent should do.

`gh aw compile` turns the Markdown file into an ordinary GitHub Actions workflow, a `.lock.yml` file next to it.
GitHub runs the `.lock.yml`. Commit both files, and never edit the `.lock.yml` by hand.

```text
.github/workflows/
├── pptb-intake-review.md         ← you edit this
└── pptb-intake-review.lock.yml   ← generated by gh aw compile; commit it, don't edit it
```

### How it differs from what we already have

| | Regular GitHub Actions (`build-tool.yml`, …) | Agentic workflows | Claude Code subagents (`.claude/agents/`) |
| --- | --- | --- | --- |
| Runs | In GitHub Actions | In GitHub Actions | On your machine, in your Claude Code session |
| Good for | Deterministic steps: build, test, deploy | Judgment: reviews, triage, reports | Interactive work while you develop |
| Can write | Whatever its token allows | Only the declared safe outputs | Whatever you approve in the session |
| Started by | Push, PR, schedule, manual | Same triggers | You |

Use a regular workflow when the steps are always the same. Use an agentic workflow when the job needs reading
and judgment, and its result is a report or a proposal that a person reviews.

## How a run works

A compiled workflow runs as several jobs. For the intake review:

1. **Activation** checks that the person who started the run has write access and prepares the prompt.
2. **Agent** checks out the repository, runs our custom `steps:` (install, build, test, audit, validate), then
   starts the agent in a sandbox. The agent's GitHub token is **read-only**, and a firewall only lets it reach
   the domains listed under `network:`.
3. **Detection** has a separate model scan what the agent produced for anything suspicious (for example a
   leaked secret or an injected instruction) before anything is written.
4. **Safe outputs** carries out the agent's requests, here creating one issue. Only this job has write
   permission, and only for the actions declared under `safe-outputs:`.
5. **Conclusion** reports the result and posts a failure report if a job failed.

The agent never holds a write token. It can only *ask* for the outputs you declared, and the safe outputs job
checks each request against those limits.

## One-time setup

You need this once per machine and once per repository.

### 1. Install the CLI extension

You need the [GitHub CLI](https://cli.github.com/) (`gh`), signed in to an account with write access to the
repository.

```bash
gh extension install github/gh-aw
gh aw version          # this guide was written against v0.89.21
gh extension upgrade gh-aw   # later, to update
```

### 2. Add the engine secret

The intake review uses the Claude engine (`engine: claude`), which needs an Anthropic API key in the repository
secrets. Claude subscription tokens (`CLAUDE_CODE_OAUTH_TOKEN`) aren't supported.

```bash
gh aw secrets set ANTHROPIC_API_KEY
```

`gh aw secrets bootstrap` checks every workflow in the repository and asks for any secret that's missing.

To use GitHub Copilot instead, see [Switching the engine](#switching-the-engine).

### 3. Approve new secrets and actions on the first compile

`gh aw compile` runs in *safe update mode*. The first time a workflow uses a secret or action that the repository
hasn't used before, the compiler stops and lists it under **SECURITY REVIEW REQUIRED**. Check that each one is
expected (for the intake review, `ANTHROPIC_API_KEY` is the engine key) and then approve it:

```bash
gh aw compile pptb-intake-review --approve
```

Mention approved secrets and actions in the pull request description, so a reviewer sees them.

### Files gh-aw adds to the repository

| File | Purpose |
| --- | --- |
| `.github/workflows/<name>.md` | The workflow you edit. |
| `.github/workflows/<name>.lock.yml` | The compiled workflow GitHub runs. |
| `.github/aw/actions-lock.json` | The commit SHA each action is pinned to. |
| `.gitattributes` | Marks `*.lock.yml` as generated, so GitHub collapses them in diffs. |

Commit all of them.

## The marketplace intake review

[`.github/workflows/pptb-intake-review.md`](https://github.com/aidevme/PPTB-Tools/blob/main/.github/workflows/pptb-intake-review.md)
runs the same review as this Claude Code prompt:

> Review tools/dataverse-early-bound-typescript-generator for marketplace intake readiness.

It checks a tool against the **live** PPTB [marketplace](https://docs.powerplatformtoolbox.com/policies/marketplace)
and [AI-assisted development](https://docs.powerplatformtoolbox.com/policies/ai-assisted-development) policies,
following the repository's `intake-policy-review` skill, and opens an issue with the result.

### What it does

1. **Builds and checks the tool.** Before the agent starts, a plain workflow step runs `npm ci`,
   `npm run build`, `npm test`, `npm audit`, `npm audit --omit=dev` and `npm run validate` (`pptb-validate`) in
   the chosen tool's folder. Each command's output and exit code goes to `/tmp/gh-aw/intake/`. A failing
   command doesn't stop the run: a failed build is a finding for the review.
2. **Reviews the tool.** The agent reads `.github/skills/intake-policy-review/SKILL.md` and follows it. It
   fetches the current policy pages, reads the tool's code, manifest, README, docs and testing records, and
   reads the command results from step 1.
3. **Reports the result.** It creates one issue titled
   `[Agentic Workflow]: Intake review of <tool display name>: <verdict>`, labelled `agentic-workflows` and
   `marketplace-intake`. The body follows the [Agentic Workflow issue template](https://github.com/aidevme/PPTB-Tools/blob/main/.github/ISSUE_TEMPLATE/agentic_workflow.yml): the run link, any failed
   commands, the trigger and inputs, then a **Review** section with the review table, the numbered findings, the
   recommended pre-submission changes and the final verdict. A newer review closes
   the older open one, so there's only ever one open review.

### Run it

**From GitHub:** go to **Actions → PPTB marketplace intake review → Run workflow**, pick the tool and click
**Run workflow**.

**From the terminal:**

```bash
gh aw run pptb-intake-review --raw-field tool=dataverse-early-bound-typescript-generator
```

The command prints the run's URL. The agent step is capped at 30 minutes (`timeout-minutes`).

`gh aw run` dispatches the workflow on your current branch by default. Use `--ref main` to review what's on
`main`, or `--push` to commit and push your local changes first and then run on them.

### Read the result

Open the issue the run created (filter by the `marketplace-intake` label). Its last line links back to the run.
The verdict is one of:

| Verdict | Meaning |
| --- | --- |
| 🟢 Marketplace-ready | Submit it. |
| 🟡 Very close / minor changes | Fix the listed items first. |
| 🟠 Not ready yet / material changes required | Material work is needed. |
| 🔴 Significant compliance or safety concerns | Stop and fix the safety or compliance issues. |

The review is a starting point for a person, not a sign-off. In particular, it can't test the tool inside
Power Platform ToolBox against a real environment: it reports that status from the tool's own testing records
([`contributing/testing.md`](../pptb-tools/dataverse-early-bound-typescript-generator/contributing/testing.md) for
the TypeScript generator).

### Review another tool

The tool is a `choice` input, so only listed tools can be reviewed. To add one:

1. Add the folder name under `on.workflow_dispatch.inputs.tool.options` in `pptb-intake-review.md`:

   ```yaml
   options:
     - dataverse-early-bound-typescript-generator
     - my-new-tool
   ```

2. Recompile and commit both files (see [Change a workflow](#change-a-workflow)).

The tool needs the usual npm scripts: `build`, `test` and `validate`. A missing script shows up in the
review as a failed command.

### Why it's built this way

| Choice | Reason |
| --- | --- |
| `workflow_dispatch` only | A review costs API credits and its findings need someone to act on them, so a person starts it. |
| `choice` input for the tool | Only real tool folders can be passed, so the input can't be used to inject text into the step or the prompt. |
| Commands run in `steps:`, not by the agent | The results are real command output, the agent's own shell stays limited to read-only commands (`cat`, `ls`, `grep`, `find`, …), and npm doesn't run inside the agent's sandbox. |
| `edit: false` | The review only reads; it can't change files. |
| `network:` lists only `defaults`, `github`, `node` and the two PPTB domains | The agent can fetch the policies and API docs and nothing else. |
| One `create-issue` with `close-older-issues` | One open review per run, and older ones close automatically. |
| The prompt tells the agent to treat repository content as data | Text in a README, an issue or a fetched page can't redirect the agent. |

### The workflow file, annotated

```yaml
---
description: Review a PPTB tool for marketplace intake readiness ...

on:
  workflow_dispatch:            # manual runs only
    inputs:
      tool:
        type: choice            # only the listed folders can be chosen
        options:
          - dataverse-early-bound-typescript-generator

permissions:                    # what the agent's GitHub token may read; it's never write
  contents: read
  issues: read
  pull-requests: read

engine: claude                  # needs the ANTHROPIC_API_KEY secret
timeout-minutes: 30             # cap on the agent step

concurrency:
  job-discriminator: ${{ github.run_id }}   # each run gets its own slot

network:                        # the firewall's allowlist for the agent
  allowed:
    - defaults                  # certificates, OS package mirrors, ...
    - github
    - node                      # the npm registry
    - docs.powerplatformtoolbox.com
    - www.powerplatformtoolbox.com

tools:
  github:
    toolsets: [repos]           # read repository content through the GitHub API
  web-fetch:                    # fetch the policy pages
  edit: false                   # no file changes
  bash: ["cat", "ls", "find", "grep", ...]   # read-only shell commands

steps:                          # plain Actions steps that run before the agent
  - uses: actions/setup-node@v5
  - name: Build, test, audit and validate the tool
    env:
      TOOL: ${{ github.event.inputs.tool }} # passed as an env var, not pasted into the script
    run: |
      ...

safe-outputs:                   # the only writes the agent can request
  create-issue:
    title-prefix: "[Agentic Workflow]: "        # same as the issue template
    labels: [agentic-workflows, marketplace-intake]
    max: 1
    close-older-issues: true
---

# PPTB marketplace intake review
Review `tools/${{ github.event.inputs.tool }}` ...   ← the prompt
```

The body can use a small set of `${{ }}` expressions, such as `github.event.inputs.*`, `github.repository` and
`github.run_id`. gh-aw passes them to the prompt safely. Other expressions are rejected at compile time.

## Change a workflow

1. Edit the `.md` file.
2. Compile it in strict mode:

   ```bash
   gh aw compile pptb-intake-review --strict --validate
   ```

   Strict mode enforces the security rules we rely on: no write permissions for the agent, an explicit
   `network:` list and SHA-pinned actions. Fix any errors and warnings it reports.
3. Commit the `.md`, the regenerated `.lock.yml` and any change to `.github/aw/actions-lock.json` in the same
   commit.

`gh aw compile --watch` recompiles on every save while you iterate. To try a change without running it in this
repository, `gh aw trial ./.github/workflows/pptb-intake-review.md` runs it in a temporary private repository.

The `.github/skills/intake-policy-review/` skill is part of the prompt: change the review procedure there, not in
the workflow. Keep it identical to `.claude/skills/intake-policy-review/`, which Claude Code uses locally, so a
local review and a workflow review follow the same rules.

## Monitor and debug runs

| Command | What it shows |
| --- | --- |
| `gh aw status` | Each workflow, whether it's enabled, and its labels. |
| `gh aw logs pptb-intake-review` | Downloads the recent runs' logs and artifacts and summarizes them: duration, token use, cost, tool calls, blocked network requests. |
| `gh aw audit <run-id>` | A detailed report for one run. Accepts a run ID or a run, job or step URL. |

In the Actions run itself:

- The **agent** job's step summary shows the agent's conversation, including what it read and fetched.
- The firewall logs list every network request the agent made, and which were blocked.
- The **safe outputs** job shows the issue it created.

## Troubleshooting

| Symptom | Likely cause and fix |
| --- | --- |
| Compile stops with **SECURITY REVIEW REQUIRED** | A new secret or action. Review it, then compile with `--approve`. See [One-time setup](#one-time-setup). |
| The run fails at **Validate ANTHROPIC_API_KEY secret** | The secret is missing or empty. `gh aw secrets set ANTHROPIC_API_KEY`. |
| The review says a policy page couldn't be fetched | The domain isn't under `network.allowed`. Add it, recompile, and say why in the PR. |
| The review reports `npm ci` failed | `package-lock.json` is out of date or missing for that tool. Run `npm install` in the tool's folder and commit the lockfile. |
| No issue was created | Check the **detection** job (it may have blocked the output) and the **safe outputs** job. The agent may also have reported `missing_tool` or `noop`; see the agent job summary. |
| The tool you want isn't in the **Run workflow** list | Add it to the `options` list and recompile. See [Review another tool](#review-another-tool). |
| `gh aw compile` warns that an action is outdated | Advisory only. Update the version in the `.md` and recompile when you choose to. |

## Switching the engine

Workflows don't depend on the engine, so you can switch with one line:

```yaml
engine: copilot
```

The Copilot engine needs either `copilot-requests: write` under `permissions:` (billed to the organization) or a
`COPILOT_GITHUB_TOKEN` secret holding a fine-grained PAT with Copilot Requests access. Recompile after switching.
The skill lives under `.github/skills/`, which works for both engines.

## Cost and limits

- Every run uses model tokens, billed to the Anthropic API key (or to Copilot). `gh aw logs` shows each run's
  token use and cost.
- `timeout-minutes` caps the agent step. Lower it if runs regularly finish early.
- Only accounts with write access can start a run (`roles` defaults to admin, maintainer and write).

## Ideas for more workflows

The [article](https://aidevme.com/github-agentic-workflows-the-next-evolution-of-repository-automation-for-power-platform-and-enterprise-developers/)
describes more workflows for Power Platform repositories. In this repository, these would fit:

- **Docs sync:** when a tool's `src/` changes, propose updates to its pages under `docs/pptb-tools/`.
- **CI doctor:** when a tool's build workflow fails, investigate and open an issue explaining the failure.
- **Issue triage:** label new issues (bug, port request, docs) and ask for missing details.

Start each one read-only and reporting to an issue. Allow pull requests only once its reports are reliable.

To propose a workflow, change one, or report a problem with a run, open an issue with the
[**Agentic Workflow**](https://github.com/aidevme/PPTB-Tools/issues/new?template=agentic_workflow.yml) template. It
asks for the decisions a workflow file needs: the trigger, inputs, what it may write and which domains it must
reach. It labels the issue `agentic-workflows`.
