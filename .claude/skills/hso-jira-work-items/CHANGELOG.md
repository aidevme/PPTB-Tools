| 2026-08-10 | Meghan Reed | Initial creation for #715. Adapted from ForgeNetherlands `atomic-atlassian-jira-backlog` @ `45ec82c` (2026-08-07) under the conformance contract in `agent/work/specs/forge-netherlands-skill-adoption/spec.md`. Renamed per convention — `hso-jira-work-items` deliberately mirrors `hso-ado-work-items` so an agent routing between a Jira-based and an ADO-based client reads them as siblings; anchored to the `delivery-tooling` topic created for this adoption. **Auth de-duplicated across five scripts.** Each carried its own copy of the `.env` discovery, the `ATLASSIAN_*` resolution, and the Basic-header construction — five places for one auth defect to hide, which is exactly what [ADR 0019](../../../agent/wiki/decisions/0019-shared-scripts-as-sibling-library-skill.md) exists to prevent. All five now dot-source [`hso-atlassian-auth`](../hso-atlassian-auth/SKILL.md), which sits outside `hso-shared-scripts` because [ADR 0060](../../../agent/wiki/decisions/0060-shared-scripts-owns-entra-auth-providers-only.md) confines that library to Entra providers and Atlassian Cloud is HTTP Basic. **Dead code removed.** Replacing the auth blocks orphaned `Resolve-ConfigRepoRoot` in every script — a helper whose only purpose was walking up the tree looking for `.env` / `.env.local`. Confirmed orphaned (one reference each, the definition itself) before deletion. Combined with the auth de-duplication the five scripts drop from **2,455 to 1,796 lines**, about 27%, with no loss of function. **`JIRA_ALLOWED_STATUSES` kept, and given the same resolution path.** Two scripts read it from `.env` upstream; it is a guardrail fencing which status transitions the skill may perform, so losing it would have quietly widened what an agent can do to a client's backlog. It now resolves through a new `Get-AtlassianSetting` helper added to the auth library, so Atlassian is configured in one place rather than two. **Parameter documentation corrected** — every script's `.PARAMETER` block still promised resolution "from .env/.env.local", which would have been actively misleading after the rewire. Kept the source's confirmation gate on all writes and sharpened the reasoning: the bulk operations touch issues the caller never named individually, and on a live client backlog that is not recoverable by undo. Kept its refusal to write priority or unlisted fields. Verified: all five parse under Windows PowerShell 5.1 (5.1.26100) and PowerShell 7 (7.6.3), pure ASCII so no BOM required (ADR 0058), no `.env` or `base64Credentials` residue, and the auth dot-source proven to fire by invoking a script with its mandatory parameter and observing the shared library's settings-missing error. **Not verified against a live Jira instance** — no credentials available in this environment, so every REST path is carried over from the source unproven, and the SKILL.md carries a dated callout saying so. |
| 2026-09-03 | Ivan Kurtev (with Claude) | **First live run - and all five scripts were broken.** Run against a real Jira Cloud tenant for the first time (a client backlog; no client data kept here). Reads worked. Every write script had lost its input-validation block in the 2026-08-10 auth de-duplication: `$fields` and `$isSubTask` never assigned in Create, `$hasDescriptionUpdate` / `$hasSummaryUpdate` in ContentUpdate, `$allowedStatuses` in StatusUpdate, `$hasAssigneeAction` / `$hasStatusAction` in AssigneeUpdate - each would have thrown under Set-StrictMode on first use. Restored and extended. **New sibling library `scripts/Jira-Common.ps1`** (ADR 0019 reasoning): REST wrapper that surfaces Jira's error body, field NAME -> id resolution against the tenant catalog (throws on unknown or ambiguous), schema-aware value shaping (textarea -> ADF, option, multi-select, components, numbers), markdown-ish -> ADF (consecutive lines become one paragraph with hard breaks so Gherkin steps stay together; headings, lists, tables, code fences), ADF -> text, paginated `/search/jql` (nextPageToken, cap 1000 - the old scripts silently stopped at 100), allowed-status guardrail, transition finder that matches the DESTINATION status before the transition name (workflows name them differently: 'Start Review' -> 'In Review'). **Create** now takes `-ParentIssueKey` for ANY type (Story -> Epic, Epic -> Theme), `-Labels`, `-Components`, `-Fields @{ 'Display Name' = value }` / `-FieldsJsonFilePath`, `-DryRun`; duplicate guard is parent-scoped; read-back verification. Fixed a shadowing defect found in dry-run: the internal `$fields` hashtable overwrote the `-Fields` parameter (PowerShell variables are case-insensitive), so custom fields were silently dropped - renamed to `$issueFields`. **ContentUpdate** adds parent, labels replace/add/remove, components, custom fields, `-DryRun`. **StatusUpdate** adds `-DryRun`, destination-status matching. **AssigneeUpdate**: restored validation (one selector, one intent, `-ConfirmUpdate` gate); fixed exact-match resolution, which failed for every user because PowerShell 7 returned the user-search JSON array as one nested Object[] - unrolled explicitly; child lookup now paginates. **Read** adds `-IncludeFields` (any field by name, rendered as a section), `-SummaryOnly`, pagination to 1000. **New `Invoke-JiraIssueBulk.ps1`**: JSON manifest with `@ref` parent references, `{ "file": ... }` values, defaults merged into every create, sub-tasks per item, duplicate ADOPTION (same summary + parent -> record key, do not create), crash-safe result file that makes re-runs idempotent, per-item isolation, `-DryRun`. Example manifest in `references/`. SKILL.md rewritten: verification callout replaced with the dated result, projection rules pointed at a per-repo `jira-projection-profile.md` (the Jira twin of ADR 0051) so no client field names or status names live in the skill. **Verified live:** GetIssue with extra fields, SearchJql paginating to 119 results, dry-run payloads for create / update / status / assignee / bulk, ADF round trip, parse under PowerShell 5.1 and 7.6, pure ASCII. **Not yet verified live:** an actual create/update/transition write - the first confirmed write on a client backlog is a deliberate human decision, not a test. Breaking: `-ConfirmUpdate` is now required on AssigneeUpdate for non-dry runs (it was documented but unenforced). |
| 2026-09-10 | Ivan Kurtev (with Claude) | **Inline markdown reached Jira as literal characters.** `ConvertTo-JiraAdf` handled block structure - headings, bullet and numbered lists, pipe tables, code fences - but nothing inside a line, so an author's `**not**` was projected as the four asterisks around the word and shown to the reader that way. Found on a live DCFS story (FIN-1593) where two sentences meant to be bold read as `**...**` in the client's Jira; three of fifteen projected stories carried it. New `ConvertTo-JiraInlineNodes` parses one line into ADF text nodes with real marks - `` `code` ``, `**strong**`, `__strong__`, `~~strike~~`, `*em*`, `_em_`, `[text](url)` - earliest match first, recursing so marks nest (`**bold with *italic* inside**`). A code span's content is literal, so markers inside it survive. Deliberately conservative: an unmatched or lone marker is left exactly as typed, so `3 * 4`, `snake_case_name` and a stray `**` are untouched, and `__strong__` needs a non-word character on each side. Wired into paragraphs (and therefore list items and table cells) and headings; fenced code blocks still bypass it. Prose with no markers produces the same single text node as before, so nothing already projected changes shape. **Marks cross a soft line break.** The first cut parsed line by line, which missed the very case that started this: hand-wrapped prose opens the bold marker at the end of one line and closes it on the next, so nothing matched and FIN-1593 stayed literal after the first re-projection. Paragraph lines are now joined before parsing, matching is Singleline, and a newline inside a marked run becomes a hardBreak node - the emphasis survives the wrap and the layout is unchanged. The reach is bounded by the paragraph, since a blank line has already ended it. **Verified:** sixteen conversion cases under PowerShell 7 covering plain prose, each mark, nesting, code-span literals, links, false positives, headings, bullets and tables; parses under 5.1 and 7; pure ASCII. |
