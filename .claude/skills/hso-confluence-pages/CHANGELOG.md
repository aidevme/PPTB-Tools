| 2026-08-27 | Ivan Kurtev | **First live run, and the gaps it exposed closed.** On 2026-08-27 the skill was exercised for the first time against a real Confluence Cloud instance (a client project's wiki, read-only). Auth, space resolution, `ListPages`, `SearchPages`, and `GetPage` (up to a 65 KB macro-heavy page) all worked first try. **Read is now verified; `CreatePage`/`UpdatePage` remain unproven** — the only live instance available was a client's wiki and writing there was deliberately avoided — so the "never run live" callout is narrowed to the write operations, not deleted. **Pagination defect fixed.** `ListPages` returned at most one API page: `-MaxResults 500` still returned exactly 250 results and the space was silently truncated alphabetically — a truncated list presented as a complete answer. All list/search operations now follow the `_links.next` cursor until exhausted; `-MaxResults 0` means "all"; the old hard clamp to 250 is gone; and any cap that cuts a list off SAYS so in the output ("showing the first N — more exist") instead of presenting the truncation as the whole. Verified live: a space that previously showed 250 pages lists 708. **`ListSpaces` added** (v2 `/spaces`, paginated; key/id/name/type/status). Defaults to `-SpaceType global` because personal spaces outnumber team spaces ~10:1 and are noise for discovery; `-SpaceType all` includes them. **`SearchContent` added — CQL full-text search**, the highest-value gap: `SearchPages` matches titles only, so finding a standard in a large unfamiliar space meant listing everything and grepping titles. Uses the v1 `/wiki/rest/api/search` endpoint (v2 has no CQL equivalent), optional `-SpaceKey` fence, paginated, reports "showing X of totalSize". Implementation note: the v1 response carries case-insensitive duplicate JSON keys (`subType`/`subtype`) that PowerShell's parser cannot represent — `Invoke-RestMethod` silently returns an unparsed string — so the operation fetches raw and strips the duplicate before parsing. **`GetPage -AsText` added**: converts storage format (XHTML + `ac:` macros) to readable markdown-style text — headings, tables (including headerless ones), lists, links, code macros to fenced blocks, entities decoded, macros reduced to `[macro: name]` stubs. Lossy by design and documented as such; storage format stays the default because `UpdatePage` round-trips it. `-OutFile` writes the body (either format) to a file. **Capture bridge considered and rejected**: a `-Capture` switch writing straight into a consuming repo's `agent/raw/` would encode that repo's wiki layout into shared IP and duplicate the ingest skills' contract; the documented seam is `GetPage -AsText -OutFile` feeding `hso-wiki-capture`/`hso-wiki-ingest-discovery-artifact`. **Docs corrected**: SKILL.md examples referenced a nonexistent `-MarkdownFile` parameter; the real one is `-BodyFilePath`. `hso-atlassian-auth` behaved correctly throughout and is unchanged. Parses clean under Windows PowerShell 5.1 and PowerShell 7; converter covered by a fixture test plus the live 65 KB page. |
| 2026-08-10 | Meghan Reed | Initial creation for #715. Adapted from ForgeNetherlands `atomic-atlassian-confluence-docs` @ `45ec82c` (2026-08-07) under the conformance contract in `agent/work/specs/forge-netherlands-skill-adoption/spec.md`. Renamed per the `hso-<domain>-<purpose>` convention; anchored to the new `delivery-tooling` topic created for this adoption (ADR 0008, spec decision D3). **Auth rewired.** The upstream script resolved `ATLASSIAN_*` from `.env` / `.env.local` and built the Basic header inline — about 130 lines of settings discovery duplicated in every Atlassian script. That block is replaced by a dot-source of [`hso-atlassian-auth`](../hso-atlassian-auth/SKILL.md), which lives outside `hso-shared-scripts` because [ADR 0060](../../../agent/wiki/decisions/0060-shared-scripts-owns-entra-auth-providers-only.md) confines that library to Entra providers and Atlassian is HTTP Basic. Script drops from 1,203 to 1,092 lines with no loss of function. **Encoding defect fixed, demonstrated rather than assumed.** The source carried four em-dashes (U+2014) in comments and `Write-Warning` strings with no UTF-8 BOM. Run under Windows PowerShell 5.1 the file is read as Windows-1252 and the character renders `â€"` — verified live, against PowerShell 7 rendering it correctly (the exact divergence class [ADR 0058](../../../agent/wiki/decisions/0058-powershell-7-run-host-and-behavioral-parity.md) documents). Two of the four were in warnings a user would actually see. Converted to ASCII hyphens rather than adding a BOM: a pure-ASCII script cannot be broken by tooling that silently drops the BOM, and it matches the other scripts adapted in this effort. Both hosts now render identically. **Scope fenced explicitly.** Added a three-way distinction the source lacks — our `agent/` knowledge base, a client's Confluence, and a Confluence page treated as an immutable *source* under ADR 0003 — because conflating them is how our internal material ends up on a client's wiki. Wired `hso-client-deliverable-standards.md` §7 as the authority for what may leave the building: publishing to a client's Confluence *is* publishing, and doing it via an API rather than an attachment changes nothing about which content is allowed to go. That link was absent from the source, which has no equivalent standard. Kept the source's `-ConfirmWrite` gate on `CreatePage`/`UpdatePage` and sharpened the reasoning: an update **replaces** a page body, so a wrong `PageId` overwrites an unrelated page as willingly as the right one. **Recorded a boundary gap rather than leaving it implicit.** Wiring §7 as the authority states the rule but does not enforce it, and the sibling `hso-client-publish` *does* enforce its equivalent — policy file, hard exclusions, scrub, dry-run, destination remapping. An authority link beside a skill whose counterpart auto-scrubs invites the assumption that this one scrubs too, which is the dangerous reading. The skill now says plainly that it enforces nothing and the caller applies the boundary by hand, and points at #728 where closing the gap properly is tracked and deliberately deferred until a real Confluence publishing scenario exists to design against. Parses clean under Windows PowerShell 5.1 (5.1.26100) and PowerShell 7 (7.6.3); the settings-missing path was exercised end to end and correctly surfaces the shared library's message. **Not verified against a live Confluence instance** — no credentials available in this environment, so every REST path is carried over from the source unproven. |
